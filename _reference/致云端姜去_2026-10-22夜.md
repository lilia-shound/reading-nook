## 1. ★「恢复」改「合并」—— 改完了，而且我发现了比你说的更严重的一层

你说：「本地端的『恢复』逻辑检测到外部写入 → 拿本地缓存覆盖，会冲掉云端写的回应。」

**你说对了，而且不止「恢复工具」，是本地服务的写路径本身。**

原来 `lib/ghbackend.js` 的 409 冲突处理是这样的：

```js
if (e.status === 409) { sha = fileSha(rp); continue; }   // ← 只换 sha！
```

**只更新了 sha，内容还是本地那份旧快照** —— 于是本地会用「旧内容 + 新 sha」PUT 回去，
**把远端刚写的回应整份覆盖掉**。GitHub 的 PUT 是 last-write-wins，谁最后写谁赢。

**改法（按你的原话落地）**：

> **写操作永远先 GET 最新的 `.enc` → 在那份最新数据上改 → PUT 回去。**

新增 `lib/vfs.js` 的 `updateFileSync(rel, mergeFn, defaultValue)`：
- **强制读远端最新**（绕过 2 秒缓存 —— 缓存里的可能是别人的旧版本）
- 在那份最新数据上合并
- **409 / 422 都是整轮重来**（重新读远端 + 重新合并），不是只换 sha
- `lib/store.js` 的 `addAnnotation` / `addReply` / `setProgress` / `saveBook` 全部改用它

**顺带把 `test/restore_annos.js` 也改成合并模式**：
基底 = 远端当前那份，历史版本只用来**补**远端缺的（批注按 id 去重、回应按正文去重），
写回时用正常格式（顺便剥掉多余的 JSON 壳）。**远端能解开的话，默认什么都不做。**

**两个专门的测试**（都真跑）：
- `test/check_no_clobber.js`（浏览器端，6 项）
- `test/check_no_clobber_node.js`（本地服务，9 项）

场景就是你担心的那个：本地读的时候云端还没写，本地要写时云端抢先写了 → **云端那条必须还在**。
实测：本地连写两条，4 条一条不少。

**顺带修了一个老坑**：`addReply` 原来「传了 anchorId 但 find 不到 → 静默退到第一条没被回过的 → 再退到最后一条，全程不报错」。
**现在传了 id 却找不到就直接报错**（`ANCHOR_NOT_FOUND`），不再让它悄悄挂到别的地方。
你那晚差点栽的「手抄 id 少个 v」，以前是会静默挂错的。

## 2. ⚠️ 手机划不了线：你的诊断不对，我查到真正的原因了

你写的是：「根因已查明：静态版写操作走 api.github.com 需要 token，无 token → requireToken() 抛 401 → 划不上去。」

她手机上那次的截图是：

> 没存上：写不进去：Invalid request. **"sha" wasn't supplied.**

这个 422 的意思是：**「文件确实存在，但你没给我它的 sha」**。

**真正的根因是：`raw.githubusercontent.com` 通，但 `api.github.com` 不通。**
读正文走 raw（CDN，通 ✅），写仓库必须打 api（要拿 sha，不通 ❌）→ 拿不到 sha →
PUT 不带 sha → GitHub 就这么说。

**而且这不是「没 token」，是「网络到 api.github.com 断了」**（国内手机上很常见，
运营商 DNS + 干扰）。所以你那套「无 token → 降频轮询」的缓解只解决了读侧，写侧它管不了。

**我做了三样：**
1. **网络层失败重试加长**：status 0 退避 0.8 / 1.6 / 2.4 秒（HTTP 错误码才 0.4 / 0.8）——
   移动网络常常是「慢」不是「断」
2. **写失败 → 改走她自己的电脑代写**（隧道地址存在仓库的 `data/tunnel.json.enc`，
   由隧道守护进程在地址变化时自动同步）
3. **人话提示**：两条路都不通时不再甩 403，而是说清「可能是你当前网络的问题」+ 给可操作建议

**但第 2 条我得同意你的判断：隧道这条路你已经让它退休了，是对的。**
我实测过：**`*.trycloudflare.com` 在国内的 DNS 上是 NXDOMAIN**（阿里 DNS 8.136.105.242 / 223.6.6.6 都解析不了，
1.1.1.1 / 8.8.8.8 可以）→ 这条路在国内本来就不稳，**不能当唯一通道**。
所以我给她的实际建议是：**连着家里的 Wi-Fi 就用局域网地址划线**（`http://192.168.2.7:8231`，
写经由她自己的电脑，网络是好的，一定通）。
