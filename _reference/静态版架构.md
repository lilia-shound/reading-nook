# 共读小屋 · 静态版（GitHub Pages）架构契约

> 这份是**实现契约**。浏览器端和 Node 端都照着它写，两边不许各写各的。

## 0. 一句话

**GitHub 仓库 = 唯一的事实来源。** 仓库里存的是**密文**。
密码不落在任何地方（不在仓库、不在构建产物、不在配置文件），它只在她输入的那一刻被用来派生密钥。

```
姜来（手机/电脑）  ──读──▶  raw.githubusercontent.com   （免 token，公开仓库）
     │                                                  ▲
     │  ──写（PUT contents，要 token）──▶ api.github.com  │
     ▼                                                  │
姜去（伴读 AI）  ──读/写──▶ 同一个仓库（带 token）
```

## 1. 仓库

- `lilia-shound/reading-nook`（**公开**，因为免费版 GitHub Pages 只支持公开仓库）
- 分支 `main`
- 静态站点由 `.github/workflows/deploy.yml` 部署到 `https://lilia-shound.github.io/reading-nook/`

## 2. 数据布局（仓库里的 `data/`）

**所有 `data/` 下的文件都是密文**（后缀 `.enc`），只有一个例外：

```
data/
  library.json.enc                          书架：书对象数组（同本地 library.json）
  books/<bookId>/
    book.json.enc                           单本书元数据（同本地）
    text.txt.enc                            正文全文
    annotations/<ch>.json.enc               该章批注数组
    notes/<ch>.md.enc                       该章剧情笔记
    progress.json.enc                       阅读进度
  docs/<docId>.md.enc                       资料库文档
```

路径一律 **POSIX 斜杠**，相对 `data/`。

> **不维护索引文件。** 需要知道「哪些章有批注」时，用 GitHub 的目录列表接口
> `GET /repos/{o}/{r}/contents/data/books/{id}/annotations` 一次拿到，不靠猜、不靠索引。
> 这样就少了一个「谁忘了更新索引」的 bug 来源。

## 3. 加密格式

**唯一实现：`public/vault.js`（UMD，浏览器和 Node 都 require 同一份）。** 禁止另写一份。

```js
// 明文 → 仓库里存的样子
{
  "v": 1,
  "alg": "AES-GCM",
  "iv": "<base64, 12 字节随机>",
  "ct": "<base64 密文>",
  "mtime": 1729700000000     // 毫秒时间戳，写入时打上，同步/判重用
}
```

- 密钥：`PBKDF2-SHA256(password, salt, iter=210000) → AES-256-GCM 256 位`
- `salt` 和 `iter` 在 **`public/site.json`**（**故意公开**，盐不是秘密，密钥才是）
- 加密用 `mtime` 是为了两台设备都能判断「谁更新」

### site.json

```json
{
  "mode": "static",
  "owner": "lilia-shound",
  "repo": "reading-nook",
  "branch": "main",
  "kdf": { "algo": "PBKDF2-SHA256", "iter": 210000, "salt": "<base64>" },
  "names": { "user": "姜来", "ai": "姜去" },
  "subtitle": "姜来 & 姜去",
  "login_hint": "两个人的生日相加"
}
```

**本地跑（node server.js）时，`server.js` 会拦截 `/site.json` 返回 `{"mode":"local"}`**，
所以同一份 `public/` 既能本地跑也能公网跑，不用维护两套。

## 4. GitHub API 用法

| 用途 | 接口 | 要 token |
|---|---|---|
| 读文件（免 token，CDN 快） | `GET https://raw.githubusercontent.com/{o}/{r}/{branch}/{path}` | 否 |
| 读文件（要新鲜，刚写完时用） | `GET https://api.github.com/repos/{o}/{r}/contents/{path}?ref={branch}`，`Accept: application/vnd.github.raw` | 否（公开仓库） |
| 列目录 | `GET https://api.github.com/repos/{o}/{r}/contents/{dir}?ref={branch}` | 否 |
| 写文件 | `PUT https://api.github.com/repos/{o}/{r}/contents/{path}` | **是** |
| 感知「有没有新动静」 | `GET https://api.github.com/repos/{o}/{r}/commits?per_page=1` | 否 |
| 拿文件当前 sha | `GET .../contents/{path}` → `.sha` | 否 |

- 全部接口的 CORS 都是 `Access-Control-Allow-Origin: *`（**已实测**）
- 写的时候 body：`{message, content: base64, branch, sha?}`
  - 带了 `sha` 就是「更新」，不带是「新建」
  - 传错 sha → **409**，要重新读、重新合并、再写
- 写完 raw 可能几十秒才同步（CDN 缓存）→ **刚写完要立刻读到自己的东西，用 api.github.com 那条路**

### token 存哪

浏览器：`localStorage['nook.gh.token']`。**不写进代码、不进仓库、不进构建产物。**
Node：`GH_TOKEN` 环境变量，或本地（不推仓库）文件 `data/.local.json` 的 `ghToken`。

## 5. 浏览器端

`public/gh-api.js` 暴露 `window.GhApi.handle(path, opt)`：
- `path` 是**站内 API 路径**（`/api/library` 这种），`opt` 同 `app.js` 里 `api()` 的约定
  （`opt.method` / `opt.json` / `opt.raw` / `opt.filename`）
- 返回**解析好的 JSON**（不是 Response）
- 出错就 `throw new Error(msg)`，并挂 `.status`

`public/app.js` 里只改一处：

```js
async function api(path, opt) {
  if (window.__NOOK_STATIC__) return window.GhApi.handle(path, opt);
  /* 原来的 fetch 逻辑照旧 */
}
```

`__NOOK_STATIC__` 在 `index.html` 里根据 `site.json` 的 `mode` 设。

### 必须实现的接口（形状照抄 `server.js`）

| 方法 | 路径 | 返回 | 静态版怎么实现 |
|---|---|---|---|
| GET | `/api/health` | `{ok, time, login_hint}` | 读 site.json（公开，免 token） |
| POST | `/api/login` | `{ok, user_name, ai_name, subtitle, login_hint}` | 用密码派生密钥 → **试着解密 `data/library.json.enc`** → 成功才算密码对 |
| GET | `/api/library` | `{books, user_name, ai_name}` | 解密 library.json.enc，再逐本读 progress.json.enc（404 就没有） |
| GET | `/api/books/:id` | `{book}` | 从 library.json 里找 |
| GET | `/api/books/:id/chapter/:n` | `{index, title, paragraphs, totalChapters}` | 解密 text.txt.enc → 按 `startLine/endLine` 切出该章 → **切段规则照抄 server.js 的 `splitParagraphs`** |
| GET | `/api/books/:id/annotations/:n` | `{annotations}` | 解密 annotations/n.json.enc（404 → `[]`） |
| POST | `/api/books/:id/annotations/:n` | `{annotation}` | 读 → 解密 → 追加 → 加密 → PUT（读改写） |
| GET | `/api/books/:id/progress` | `{progress}` | 解密 progress.json.enc（404 → null） |
| POST | `/api/books/:id/progress` | `{progress}` | 合并 → 加密 → PUT |
| GET | `/api/notes/:id/:ch` | `{chapter,title,text}` | 解密 notes/ch.md.enc（404 → 404） |
| GET | `/api/docs` | `{docs}` | 列 `data/docs` 目录 → 逐个解密取 front-matter |
| GET | `/api/docs/:id` | `{id,title,text,...}` | 解密 docs/:id.md.enc |
| GET | `/api/pending` | `{items}` | 见下 |
| GET | `/api/ping` | `{ts, pending}` | 见下 |
| GET | `/api/formats` | `{formats:[...]}` | 静态列表 |
| GET | `/api/settings` | `{}` | 静态版设置全在前端 localStorage |
| POST | `/api/settings` | `{}` | 同上 |
| DELETE | `/api/books/:id` | `{ok:true}` | 用 token 走 API 删（有 token 才行） |

| POST | `/api/ai/auto` | — | 不支持 |
| POST | `/api/ai/reply` | — | 不支持（**姜去直接写仓库**） |

| GET | `/api/workbench` | — | 不支持 |

### `/api/pending` 和 `/api/ping` 怎么做得便宜

**不能每次轮询都扫所有章**（《古道》24 章 → 每 20 秒 24 个请求，扛不住）。

做法：
1. `GET /repos/{o}/{r}/commits?per_page=1` → 拿最新 commit 的 `sha` 和时间
2. sha 没变 → **直接返回上次算好的结果**（缓存）
3. sha 变了 → 才重算：列 `data/books` 目录 → 每本书列 `annotations` 目录 → 有批注的章才去解密读
4. `/api/ping` 的 `ts` = 最新 commit 的时间戳（毫秒）→ 前端靠它判断「姜去回批注了」

**一轮轮询正常情况下只发 1 个请求。**

### 写（划线）的完整流程

```
POST /api/books/{id}/annotations/{ch} {anchor, note, paraIndex}
  1. GET contents/{path}              → 拿 sha + 现有密文（404 就是新章）
  2. 解密 → JSON.parse → 数组
  3. push({id, anchor, note, who:'user', paraIndex, ts, replies:[]})
  4. 加密 → PUT contents/{path} {sha, content, message}
  5. 409 → 回到 1 重来（最多 3 次）
```

- `id` 格式跟本地一样：`a_` + base36 时间戳 + 随机串
- 写成功后**本地缓存立刻更新**（不等服务器），所以她马上就能看见自己划的线
- 写失败要**明确报错**，不能静默吞掉（本地版的行为是 toast 提示）

## 6. Node 端

`lib/vfs.js` 提供一套**和 fs 一样、但能换成 GitHub 后端**的接口，路径一律相对 `data/`、POSIX 斜杠：

```js
vfs.readFileSync(rel)            -> string（不存在抛错，error.code === 'ENOENT'）
vfs.writeFileSync(rel, content)
vfs.existsSync(rel)              -> bool
vfs.readdirSync(rel)             -> string[]（文件名，不含路径）
vfs.mkdirSync(rel, opts)         -> 目录不存在时也不报错
vfs.rmSync(rel, {recursive:true})
vfs.statSync(rel)                -> {size} | null
```

- 后端选择：`process.env.NOOK_BACKEND === 'github'` → GitHub，否则本地磁盘
- GitHub 后端要的东西：owner/repo/branch（site.json）、token（`GH_TOKEN` 或 `data/.local.json`）、密码（`NOOK_PASSCODE` 或 `data/.local.json`）、salt/iter（site.json）
- **没有 token 就没有写权限**：读照常，写要抛清楚的错

`lib/store.js` 改成用 `vfs`（路径改成相对 `data/` 的字符串），`lib/docs.js` 同理，`server.js` 里凡是 `path.join(store.bookDir(...))` 改成拼字符串。

**本地模式（默认）必须保持原样能用** —— 她的电脑上还在跑 `node server.js`。

## 7. 本地 ↔ 仓库 的关系

**仓库是唯一事实来源。** 本地 `data/` 只是缓存。

- 本地跑（`NOOK_BACKEND=fs`）：还是老样子，独立的本地数据
- 切到仓库模式：改 `data/.local.json`（`{"backend":"github","passcode":"...","ghToken":"..."}`）
- 迁移：把本地 `data/` 加密后推上仓库（`node tools/push-repo.js --migrate`）

## 9. 铁律

1. **密码不落盘**。仓库里、构建产物里、`data/` 里都不能有明文密码。
2. **token 不进仓库、不进前端源码**。只进 `localStorage` / 环境变量。
3. **加密只有一份实现**（`public/vault.js`）。不许复制粘贴第二份。
4. **本地模式不许坏**。`node server.js` 必须照旧能跑。
5. **不要维护索引文件**。用目录列表接口拿真实状态。
6. **请求要省**。一轮轮询 1 个请求，不是 24 个。
7. **写冲突要重试**（409 → 重读 → 合并 → 再写，最多 3 次）。
8. **失败要说人话**。静默失败是最难查的 bug。
