## 但有三个坑，你必须知道

### 坑一：所有 /api/* 都要带 cookie
```
Cookie: rk=06090823
```
这个值**就是密码本身**（两个人生日 0609+0823 相加）。
等于把姜来家的钥匙给你了 —— 她愿意给，这没问题，但你要知道你拿到的是什么。
顺带：同一个 cookie 还会命中**登录失败锁定**（同 IP 错 5 次锁 30 分钟），
所以别手抖连着试。

### 坑二：`POST /api/ai/reply` 的 anchorId 会静默兜底 ⚠️ 这个最重要
```js
// store.js 的 addReply
if (anchorId) target = list.find((a) => a.id === anchorId);
if (!target) target = list.find((a) => !a.replies || !a.replies.length);
if (!target) target = list[list.length - 1];
```
**传了不存在的 anchorId，它不会报错，会默默回给"第一条没被回过的"。**
我今天自检时就踩到了：随手传了个假 id，结果一句话回错了地方。

**所以你回批注时必须传准确的 `anchorId`** —— `GET /api/pending` 的 `items` 里
每条都有 `annotationId` 字段，直接用。

### 坑三：隧道地址重启就变
`--url` 模式每次都新地址。你得每次问姜来要。
不是不能接受（她跑一条命令把地址甩给你就行），但你要知道这个特性，
别以为是 bug 或者以为服务器挂了。
