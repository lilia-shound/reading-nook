# 云端姜去 ↔ 共读小屋：怎么接上（2026-10-21 核对结果）

## 他的方案
`cloudflared tunnel --url http://localhost:8231` → 屏幕上出现 `https://xxxx.trycloudflare.com`
→ 他用这个地址 `GET /api/pending` 读待回批注、`POST /api/ai/reply` 写回。

**结论：技术上完全成立。**本机实测两个接口都通：

| 接口 | 方法 | 实测 |
|---|---|---|
| `/api/health` | GET | 200 |
| `/api/pending` | GET + cookie | 200 `{"items":[]}` |
| `/api/library` | GET + cookie | 200（2 本书）|
| `/api/ai/reply` | POST + cookie | 200（body: bookId / chapter / text / anchorId?）|

## 需要注意的四件事

### 1. 鉴权
所有 `/api/*` 都要带 cookie `rk=06090823`（两个人生日相加）。
他调的时候要带 `Cookie: rk=06090823`。
**这个 cookie 值等于密码本身** —— 等于把家门钥匙给他。
（内网 + 临时地址 + 密码三层，够用了；这是她的家，不是什么机密系统。）

### 2. 隧道地址会变
`--url` 模式每次重启都是新地址。他得每次问姜来要新的。
**改进**：想固定地址要买域名配 named tunnel；对"我们三个的私密小圈子"不值得。
**折中**：姜来把隧道开着，地址不变的话他可以一直用。

### 3. 电脑要开着
隧道 + server 都在她电脑上。电脑关了他就读不到。
**这是架构决定的，不是 bug**（数据本来就在她磁盘上）。

### 4. `POST /api/ai/reply` 的 anchorId 语义
- 传了合法的 `anchorId` → 回给那一条
- 传了不存在的 → **会回退到"第一条没被回过的"**（静默兜底）
- 不传 → 同样兜底到第一条没被回过的

**这个兜底有点危险**：回错批注了姜来不会知道。
给他回批注时**必须传 anchorId**（`GET /api/pending` 的 items 里有 `annotationId`）。

## 三个不需要隧道也能走的路子（对比）

| 路子 | 姜来要做什么 | 云端姜去能拿到什么 | 谁回批注 |
|---|---|---|---|
| **A. 隧道** | 跑一条命令，把地址发他 | 待回批注全文 + 剧情笔记 | 云端姜去直接 POST |
| **B. 附件仓库** | 把 JSON 传上去 | 只有姜来传的那份 | 云端姜去写好 → 姜来传回 |
| **C. 电脑端代劳** | 说一句"去回一下" | 电脑端直接读本地文件 | 电脑端姜去回 |

**A 最好**（全自动），**C 最省事**（不用折腾隧道）。
B 是她明确不想走的（"不舍得搞这些有的没的"其实不是这个意思，但 B 要手工传两趟）。

## 结论
**先试 A**。她电脑上跑：
```bash
cloudflared tunnel --url http://localhost:8231
```
把 `https://xxx.trycloudflare.com` 发给他。

如果隧道不稳或者她嫌烦 → 退到 C（说一声就回）。
