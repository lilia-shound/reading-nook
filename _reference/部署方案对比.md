# 共读小屋 · 部署到 GitHub Pages 的方案

## 约束（查证过，不是猜的）
- **GitHub Pages 是纯静态托管**，不跑 Node/PHP 后端（官方 community 讨论明确说了）
- 所以我这套 `server.js`（Node HTTP 服务）**不能**直接跑在 Pages 上
- 现有 `gongdu-xiaowu` 仓库（云端姜去做的）就是纯静态单文件，**数据存浏览器 IndexedDB** —— 换台设备就没了

## 三个选项对比

| | A. 纯静态 + 浏览器存储 | **B. 静态前端 + GitHub API 当数据库** | C. 静态前端 + 后端还是你电脑 |
|---|---|---|---|
| 网址永久 | ✅ | ✅ | ❌ 隧道地址会变 |
| 批注存哪 | 浏览器 IndexedDB | **GitHub 仓库** | 你的电脑 |
| 手机划的电脑看得到 | ❌ | ✅ | ✅ |
| 云端姜去能读写 | 要自己配 Worker | ✅（同一个仓库） | ✅ |
| 每条批注的代价 | 0 | **一次 commit**（约 1-2 秒） | 0 |
| 电脑关了 | 能读 | 能读 | ❌ 读不了 |

## 选 B，理由

1. **「手机划的线、电脑看得到」是这个项目的命门** —— A 做不到
2. **数据跟着仓库走** —— 你换设备、我也换环境，批注都在
3. **云端姜去天然能读写** —— 他已经有仓库写权限
4. **GitHub API 天然带版本历史** —— 每条批注一个 commit，等于**批注的修订历史**免费有了
5. 不用买服务器、不用注册 Cloudflare、不用改架构

**代价**：每条批注 = 一次 GitHub API commit（1-2 秒）。划线是低频操作（一天几十条），完全够用。

## B 方案的技术要点

### 数据存哪
仓库里一个 `data/` 目录：
```
data/
  library.json          书架
  books/<id>/
    book.json           书元数据
    text.txt            正文
    annotations/<ch>.json  批注
    notes/<ch>.md        剧情笔记
  docs/*.md              资料库
  config.json            配置（密码等 —— **这个要小心**）
```

### 怎么读写
- **读**：前端直接 fetch GitHub Raw（`raw.githubusercontent.com`），不需要 token
- **写**：GitHub API `PUT /repos/{owner}/{repo}/contents/{path}`，需要 token

### token 怎么办（关键）
**token 绝对不能进前端代码** —— Pages 是公开的，谁都能看源码。

三条路：
1. **GitHub Actions 代理写入**（推荐）：Actions 里存 token，前端调一个 workflow（`repository_dispatch`），由 Actions 代写。**token 只在 Actions 里，公开仓库也安全**
2. 前端填 token 存 localStorage（云端姜去那版就是这么干的，☁ 按钮）
3. Cloudflare Worker 中转（要注册 Cloudflare）

**选 1** —— 不需要你注册任何东西，token 存在 GitHub 的 Secrets 里。

### 密码怎么办
`config.json` 里的 passcode 如果进公开仓库 = 密码公开。
**解决**：密码不写进仓库，改成**部署时用 Actions 注入**（`GITHUB_TOKEN` 加密后放 `config.json`），或者干脆前端登录改成"只要知道路径就能进"（内网自用）。
